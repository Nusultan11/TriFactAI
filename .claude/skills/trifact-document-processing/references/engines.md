# Выбор движков разбора и OCR

Текущий выбор проекта и его замеры — [ADR-0021](../../../../docs/architecture/adr/0021-document-processing-router.md) и [models.md §6.3](../../../../docs/research/models.md). Здесь — критерии и кандидаты для следующих экспериментов.

## Критерии (по порядку важности для TriFact)

1. **Казахский.** Модель распознаёт `ә ғ қ ң ө ұ ү һ і`. Проверка: CER kk на `pdf_scan` и матрица замен символов. Лидерборды почти не содержат kk, поэтому без своего замера кандидат не рассматривается.
2. **Структура для цитат.** Модель отдаёт страницу, блоки, порядок чтения, заголовки и таблицы, а не только сплошной Markdown. Без страниц и смещений цитата `(page, char_start, char_end)` невозможна.
3. **Ресурсы.** CPU-воркер, ~2 GB RAM на процесс парсера, локальная GPU 4 GB (архитектура §1). Модель только для GPU годится лишь для офлайн-переразбора или облачного профиля.
4. **Скорость.** НФТ — ≥ 2 стр/с на текстовых PDF; сканы — отдельный сценарий нагрузки.
5. **Лицензия.** PyMuPDF — AGPL-3.0 (ADR-0021). У ряда VLM-OCR веса с ограничениями, например модифицированный OpenRAIL-M у Chandra. Лицензия записывается в models.md до использования.
6. **Устойчивость.** Падения и зависания изолируются `SafeParser`. У GPU-моделей добавляются OOM и таймауты.

## Классы страниц и разумный первый выбор

| Класс | Первый выбор | Когда эскалировать |
|---|---|---|
| Текстовый слой, 1–2 колонки | PyMuPDF (быстрый путь) | битый слой, нет текста |
| Таблицы с линейками и без | Docling + TableFormer (FAST) | F1 ячеек на `real_docs` ниже целевой |
| Сканы 200–300 dpi | Docling + Tesseract `kaz+rus+eng` | CER > нормы на фото, наклоне, низком dpi |
| Фото телефоном, рукопись, формулы | эксперимент с VLM-OCR | — |
| DOCX, HTML, TXT | нативные парсеры | — (Docling-бэкенды проиграли по замеру этапа 4) |

## Кандидаты VLM-OCR (состояние на 2026-11)

Лидеры end-to-end лидерборда OmniDocBench v1.6 (github.com/opendatalab/OmniDocBench) — специализированные VLM размером 0.9–1.3B: PaddleOCR-VL-1.6 (Apache-2.0), MinerU2.5-Pro, GLM-OCR (MIT), а также dots.ocr (MIT, 3B, многоязычный). На olmOCR-Bench — olmOCR 2 (Apache-2.0, 7B) и Chandra OCR 2.

Ограничения переноса:

- OmniDocBench — 1 651 страница; языки в основном китайский и английский, треть итоговой оценки дают формулы.
- olmOCR-Bench штрафует колонтитулы в выходе, а для цитат и счетов они иногда важны.
- На фотографиях страниц (Wild-OmniDocBench) лидеры теряют 10–20 пунктов.
- Казахский ни один из этих бенчмарков не проверяет.

Поэтому:

1. Отобрать 2–3 кандидата по лицензии, размеру и заявленной поддержке кириллицы.
2. Прогнать их на `data/eval/docproc` (виды `pdf_scan`, `mixed`) и на `real_docs` в отдельном процессе; посчитать CER по языкам, матрицу замен казахских букв, F1 заголовков и ячеек, с/стр на доступном GPU.
3. Проверить, можно ли получить страницы и блоки с bbox, чтобы собрать `ParsedDoc` со смещениями.
4. Включать модель только для класса страниц, где она значимо лучше Tesseract (CI), как новую ветку маршрутизатора `docproc.router`. Изменённое решение оформить новым ADR.
