# 17. Raw-слой: протокол загрузки, именование таблиц, проверка строк и лицензий

Date: 2026-11-18

## Status

Accepted

Amends [11. Data lake на Parquet со слоями и манифестами](0011-parquet-data-lake.md)

## Context

В этапе 1 выяснилось, что источники разнородны. Это parquet, csv с многострочными полями, tsv без заголовка, jsonl(.gz) и arrow-stream. У части источников несколько таблиц с разными схемами: у mMARCO — collection, queries и triples, у MIRACL — topics и qrels. Сплиты заданы именами файлов. Метаданные о числе строк есть не везде: у script-датасетов (NEREL, mMARCO, MIRACL) dataset viewer их не считает, а у крупных csv считает лишь частично. Дамп Wikidata скачивается с dumps.wikimedia.org примерно на 1–1.5 MB/s на соединение, при 4 параллельных соединениях сервер отвечает HTTP 429. Полная загрузка занимает сутки, поэтому обрыв не должен отбрасывать уже скачанное.

## Decision

- **Таблицы.** Шард называется `data/raw/<source>/<lang>/<table>-NNNNN.parquet`. Для однотабличных источников `table = part`. Все шарды одной пары (`lang`, `table`) имеют одну схему, это проверяется при загрузке. `lang = multi` используется для многоязычных записей (параллельный корпус, Wikidata).
- **Колонки происхождения.** В raw-шард добавляются только `_config` и `_split` (`train` / `validation` / `test`, `valid`/`val`/`dev` → `validation`). Остальное содержимое остаётся как в источнике.
- **Описание источника** (`params.yaml: sources.<name>`): `revision` — SHA коммита, имя ветки не принимается; `files` — glob → `lang`, `table`, `config`, `split`, `columns`; `license` — решение `use: allowed | research_only | blocked` с полями `release`, `evidence`, `note`. Источник с `blocked` или без решения не скачивается.
- **Протокол загрузки (HF).** Единица работы — файл репозитория. Файл скачивается в `data/.cache/downloads` (вне DVC-outs), сверяется с sha256 LFS-указателя и конвертируется потоково в `_work/`. После этого пишется маркер `_work/<idx>.json`. Перезапуск пропускает файлы с маркером. Когда готовы все файлы, шарды атомарно переименовываются в итоговую раскладку по порядку файлов (возобновляемо через `_work/finalize.json`), пишется `source.yaml`, а `_work` удаляется. Повторный запуск при совпадающей ревизии только проверяет манифест.
- **Проверка числа строк** записывается в `row_checks` манифеста. Используется метод с наибольшей доверенностью из доступных: `hf_dataset_info` (README на зафиксированной ревизии), `hf_datasets_server` (только точные, не `partial`), `parquet_footer`, а без метаданных — независимый пересчёт `line_count` (jsonl/tsv) или `csv_record_count` (stdlib-парсер). Любое несовпадение — ошибка стадии.
- **Wikidata.** Фиксируется датированный дамп (`revision` = дата), а не `latest`. Загрузка идёт range-запросами по 64 MB в ≤ 3 соединения, готовые чанки отмечаются в state-файле, в конце сверяется опубликованный sha1. Разбор — параллельный bzip2 (`indexed_bzip2`) и пул процессов. Шард k содержит сущности `[k·N, (k+1)·N)` в порядке дампа, поэтому раскладка детерминирована, а готовые шарды пропускаются по маркерам `_progress/`. Число сущностей независимо пересчитывается читателем (`entity_count`).
- **DVC.** Выходы `acquire` и `wikidata` объявлены `persist: true`, иначе `dvc repro` удалял бы недокачанное. Кеш — `hardlink`: raw не меняется, и место на диске не удваивается.
- **Smoke-прогон** (`--limit-rows`, `--limit-entities`, `--root <tmp>`) помечает манифест `partial: true`. Такие данные в DVC не попадают.

## Consequences

Обрыв загрузки стоит не больше файлов, которые были в работе (для HF), или одного чанка 64 MB (для дампа). Каждое число строк в манифесте подтверждено независимым источником, а метод подтверждения записан. Источник с непроверенными правами нельзя скачать «по ошибке». Цена — второе чтение файла при пересчёте строк и хранение промежуточного `_work/` до конца загрузки источника.
