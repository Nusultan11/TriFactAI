# TriFact AI — инструкция по работе над проектом

Обязательна для любого агента и человека, который меняет репозиторий. Чек-листы выполняются по порядку, без пропусков.

## 1. Цель

Мультиязычная (KK / RU / EN) ML-система. Принимает документы любого вида, устойчиво извлекает сущности, ищет доказательства на трёх языках, отвечает на вопросы со ссылками на источники и проверяет свои утверждения.

Масштаб — миллионы и десятки миллионов записей. Любое решение (формат, алгоритм, модель, инфраструктура) выбирается по качеству, скорости и стоимости на этом масштабе и подтверждается замером.

## 3. Перед началом работы

1. Прочитать PROGRESS: текущий этап, блокеры, «Что учесть дальше».
2. Прочитать в ROADMAP раздел текущего этапа.
3. Если задача касается устройства системы, прочитать нужный раздел архитектуры и связанные ADR.
4. Если выбирается модель или данные, свериться с `docs/research/`. Новые проверенные факты записать туда с датой и источником.
5. Загрузить скилл области из `.agents/skills/` (Claude Code читает зеркало `.claude/skills/`). Выбор — по описанию скилла или по таблице в [README каталога](.agents/skills/README.md).
6. Выбрать следующий шаг: ближайший невыполненный подшаг текущего этапа.
7. Если шаг противоречит PROGRESS или ADR, сначала обновить документ (изменённое решение = новый ADR), затем работать.
8. Разложить этап на подзадачи в shrimp.

## 4. Выполнение этапа

Один рабочий шаг = один этап ROADMAP целиком. Каждый подшаг проходит цикл:

1. **Спроектировать**: интерфейс, формат данных, метрика и способ замера.
2. **Реализовать** только нужный код.
3. **Проверить** тестами, затем прогоном на `scale.profile: pilot`, затем на `full`.
4. **Замерить** метрики по каждому языку, throughput (записей/с), пиковую RAM/VRAM.
5. **Исправить** найденные ошибки и повторить шаги 3–4.
6. **Записать** результат в MLflow, ключевые цифры — в PROGRESS.

Этап считается закрытым, только когда выполнены все его критерии из ROADMAP.

## 5. Завершение этапа

1. `ruff check`, `ruff format --check`, `mypy src/trifact/core`, `pytest -q` проходят без ошибок.
2. Критерии готовности этапа выполнены, runs записаны в MLflow.
3. Очистка по §6.1: `ruff check --select F401,F841`; удалены мёртвые модули, конфиги, временные файлы, одноразовые эксперименты.
4. Обновлены PROGRESS (запись этапа сверху, «Текущее состояние», «Что учесть дальше»), затронутые разделы архитектуры и ADR.
5. Если менялась модель C4, проверить её и экспортировать диаграммы (архитектура §15).
6. Сделать коммит(ы) в `main` (§6.4) и `git push`.
7. Сделать бэкап: `python scripts/backup.py --tag stage-NN`.
8. Отправить отчёт пользователю по шаблону §10.

## 6. Правила

### 6.1 Чистота проекта

- Версионные копии файлов запрещены: `*_v1`, `*_v2`, `final`, `new`, `old`, `copy`, «исправленный». История хранится в git, снимки — в бэкапах.
- Пишется только код, который нужен текущему этапу и используется. Нет кода «на всякий случай», закомментированных блоков и неиспользуемых функций.
- Вариант эксперимента — это параметр (`params.yaml`, CLI), а не копия скрипта.
- Временные файлы — вне репозитория. Ноутбуки — только в `notebooks/`, без выводов (`nbstripout`).
- Данные, веса и отчёты-артефакты хранятся в DVC и MLflow, не в git.
- Скиллы правятся только в `.agents/skills/`. Зеркало `.claude/skills/` обновляет `python scripts/sync_skills.py`, формат, ссылки и синхронность проверяет `tests/test_skills.py`.

### 6.2 Данные

- Слои, шарды и манифесты — по [ADR-0011](docs/architecture/adr/0011-parquet-data-lake.md). Слой `raw` после загрузки не меняется.
- Обработка потоковая и колоночная: Polars lazy/streaming, DuckDB, PyArrow, datatrove. `pandas` для больших наборов не используется. Набор целиком в RAM не загружается.
- Массовые операции — шардированные идемпотентные задания ([ADR-0014](docs/architecture/adr/0014-sharded-batch-jobs.md)).
- Сплиты строятся по исходному документу, eval замораживается до обучения ([ADR-0007](docs/architecture/adr/0007-leakage-safe-splits.md)).
- Silver и синтетика используются только в train ([ADR-0015](docs/architecture/adr/0015-silver-and-synthetic-data.md)).
- Решение по лицензии записывается в манифест до использования источника.

### 6.3 Модели и эксперименты

- Каждый эксперимент — run в MLflow (состав run — архитектура §11) с метриками по каждому языку.
- Сравнение — с baseline на одном и том же замороженном тесте. Улучшение без значимости (архитектура §10) улучшением не считается.
- Модель продвигается только через гейт [ADR-0009](docs/architecture/adr/0009-model-registry-and-promotion-gate.md).
- Отрицательный результат тоже записывается в PROGRESS.
- Перед использованием незнакомого API библиотеки — актуальная документация через context7.

### 6.4 Git

- Работа только в ветке `main`, удалённый репозиторий — `origin` (GitHub).
- Коммиты атомарные, Conventional Commits, заголовок ≤ 72 символов, настоящее время: `type(scope): описание`. Типы: `feat`, `fix`, `refactor`, `perf`, `test`, `docs`, `data`, `exp`, `chore`, `build`.
- Минимум один коммит на этап, крупные подшаги — отдельными коммитами.
- Не коммитить секреты (`.env`), данные, веса, `__pycache__`, артефакты.
- Перед коммитом выполнить проверки из §5 п. 1.

### 6.5 Код

- Python 3.12, окружение `uv`, зависимости в `pyproject.toml` (группы `serving`, `ingestion`, `ml`, `dev`).
- Линт и формат — `ruff`; типы — `mypy` для `src/trifact/core`; тесты — `pytest` в `tests/` (структура зеркалит `src/`).
- Модули зависят от интерфейсов `trifact.core.interfaces`, а не от конкретных моделей.

## 7. Нештатные ситуации

| Ситуация | Действие |
|---|---|
| Этап нельзя закончить: нет доступа, ресурса или решения пользователя | Доделать всё, что от блокера не зависит → записать блокер в PROGRESS → коммит, push, бэкап → отчёт со статусом «остановлен» и списком того, что нужно от пользователя |
| Эксперимент не дал значимого улучшения | Champion остаётся → результат записывается в PROGRESS как отрицательный |
| Принятое решение больше не работает | Новый ADR со статусом `Supersedes`, у старого — `Superseded by` |
| Предстоит массовое удаление, переписывание или смена схемы данных | Сначала бэкап `--tag before-<что>` |
| Факт в каталоге оказался неверным | Исправить в каталоге, указать источник и дату проверки |
| Проверки перед коммитом падают | Не коммитить; исправлять причину, а не тест |
| MCP-сервер недоступен | Записать в блокеры PROGRESS; работать без него, если он не обязателен для шага |

## 8. Бэкапы

- Команда: `python scripts/backup.py --tag <метка>`. В `C:\Users\nurs\TrifactAI_backups\` появляются `git bundle` со всей историей и архив неотслеживаемого состояния (`.env`, `.shrimp/`, локальные настройки). Хранятся последние 30 снимков.
- Когда: после каждого этапа; перед массовыми удалениями и переписыванием; перед сменой схемы данных.
- Данные и модели бэкапятся через `dvc push`, а не этим скриптом.
- Восстановление: `git clone <bundle> TrifactAI`, затем распаковать архив состояния.
